One shared core carries the behavior; thin adapters expose it to each
technology. This page tracks the measured state of that work and is updated
when an adapter grows.

## Where each technology stands

| Technology | Package | Components today | State |
| --- | --- | --- | --- |
| **Svelte** | `@design-system/svelte` | All 80 | Complete: every component documented with a live demo. |
| **React** | `@design-system/react` | 37 of 80 | Being completed to the full catalog, with styled components and headless hooks. |
| **Python** ([Reflex](https://reflex.dev/)) | `invisible_ui` | 7 | Working adapter over the React components ([ADR 0006](https://github.com/dr2madre/invisible-ui/blob/main/docs/adr/0006-python-adapter-wraps-react.md)). |
| **Web components** (plain HTML) | `@design-system/elements` | All 80 | Complete: one script tag, no build step, any page ([ADR 0008](https://github.com/dr2madre/invisible-ui/blob/main/docs/adr/0008-web-components-adapter.md)). |
| **Vue** | `@design-system/vue` | All 80 | Complete: every Svelte component has a Vue counterpart, with `v-model` on the controlled values. |
| **Flutter** | `invisible_ui` (Dart) | 11 of 80 | Foundation (tokens, theme, density, focus ring, messages) and Button, Field, Text Field, Text Area, Number Field, Tooltip, Toolbar, Dropdown Menu with submenus, Inline Notification, Notification and Notification Region, each checked against the Svelte reference ([ADR 0017](https://github.com/dr2madre/invisible-ui/blob/main/docs/adr/0017-flutter-adapter.md), [parity checklists](https://github.com/dr2madre/invisible-ui/tree/main/packages/flutter/parity)). |

Svelte, Vue and the web components carry the whole catalog. The shared set
below tracks the React adapter, which is being completed to the full catalog,
and the Python wrappers over it. When a component
lands in an adapter, this page and the [API conventions](/invisible-ui/api/)
change with it.

## Native Vue example

The runnable [`examples/vue`](https://github.com/dr2madre/invisible-ui/tree/main/examples/vue)
app consumes `@design-system/vue` directly. It demonstrates the full native
adapter with `v-model`, localization, dialogs, notifications and shared theme
tokens.

## Web component interoperability

The web components run in any page that can show HTML: server-rendered
apps, older portals, and frameworks without a dedicated adapter today. A
separate Vue interoperability example lives in the repository
([examples/elements/vue.html](https://github.com/dr2madre/invisible-ui/blob/main/examples/elements/vue.html)):
the custom elements work in Vue templates as they are.
