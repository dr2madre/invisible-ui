One shared core carries the behavior; thin adapters expose it to each
technology. This page tracks the measured state of that work and is updated
when an adapter grows.

Svelte, React, Vue, the web components and Flutter carry the whole catalog of 81
components. Data Grid, the editable grid for timesheets, is outside that count:
it is built in `core/` and Flutter from its
[specification](https://github.com/dr2madre/invisible-ui/blob/main/docs/editable-grid-spec.md),
and the web adapters follow. The shared set below tracks the Python wrappers
over the React components.

Every adapter passes its automated checks: unit and interaction tests, axe,
keyboard paths, contrast and, in Flutter, the accessibility guidelines. No
component has been checked yet with a screen reader or with touch assistive
technology, so none is described as verified; the
[evidence register](https://github.com/dr2madre/invisible-ui/blob/main/docs/evidence-register.md)
records what each check covers. When a component
lands in an adapter, this page and the [API conventions](/invisible-ui/api/)
change with it.

## How to install

The Svelte, React, Vue and web components packages and the core are published
on npm as alpha releases, under the `alpha` dist-tag (`0.1.0-alpha.1` today).
APIs may change before the first stable release.

| Technology | Install | Stylesheet |
| --- | --- | --- |
| Svelte | `pnpm add @nozcadesign/invisible-ui-svelte@alpha` | `@nozcadesign/invisible-ui-svelte/tokens.css`, imported once in the app; component styles read their values from it |
| React | `pnpm add @nozcadesign/invisible-ui-react@alpha react react-dom` | `@nozcadesign/invisible-ui-react/styles.css` |
| Vue | `pnpm add @nozcadesign/invisible-ui-vue@alpha vue` | `@nozcadesign/invisible-ui-vue/styles.css` |
| Web components | `pnpm add @nozcadesign/invisible-ui-elements@alpha` | `@nozcadesign/invisible-ui-elements/styles.css` |
| Core only | `pnpm add @nozcadesign/invisible-ui-core@alpha` | None: the core renders nothing |

The React, Vue and web components packages also export `tokens.css`: the
design tokens without the component styles, for markup you style yourself.

A page without a build step can load the web components from a CDN, pinned to
an exact version: the stylesheet and `define.js`, which bundles the core. The
[Elements setup](https://github.com/dr2madre/invisible-ui/tree/main/packages/elements#usage--no-build-step-required)
shows the two tags.

The Flutter package is not published to pub.dev. A Flutter app depends on
`packages/flutter` by git, pinned to a commit; the
[Flutter setup](https://github.com/dr2madre/invisible-ui/tree/main/packages/flutter#depend-on-it)
shows the `pubspec.yaml` entry.

The Python package is not published to PyPI. Its wrappers render the
components of `@nozcadesign/invisible-ui-react`; the
[Reflex setup](https://github.com/dr2madre/invisible-ui/tree/main/packages/reflex#resolving-the-npm-package)
describes how a Reflex app resolves that npm package.

## Native Vue example

The runnable [`examples/vue`](https://github.com/dr2madre/invisible-ui/tree/main/examples/vue)
app consumes `@nozcadesign/invisible-ui-vue` directly. It demonstrates the full native
adapter with `v-model`, localization, dialogs, notifications and shared theme
tokens.

## Web component interoperability

The web components run in any page that can show HTML: server-rendered
apps, older portals, and frameworks without a dedicated adapter today. A
separate Vue interoperability example lives in the repository
([examples/elements/vue.html](https://github.com/dr2madre/invisible-ui/blob/main/examples/elements/vue.html)):
the custom elements work in Vue templates as they are.
