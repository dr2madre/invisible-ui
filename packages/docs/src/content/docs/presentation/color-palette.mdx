## The scale

An **11-weight scale** per hue, from `50` (lightest) to `950` (darkest). Pick a
semantic role and step up or down in weight for hover, active, borders and
surfaces. The scale is authored to keep perceptually even steps (checked in
OKLCH), so a weight change reads as a predictable lightness change.

- **Brand** — the primary is **Dioxazine Purple**; step to `600` for hover.
- **Feedback** — Cobalt Blue (info), Sap Green (success), Burnt Orange
  (warning), Alizarin Red (danger).
- **Neutrals** — the **Grey** ramp carries text, surfaces and borders;
  **White** sits apart at the light end and **Black**, `#121212`, a near
  black, at the dark end. **Warm Grey** stays in the palette as
  a hue of its own; it no longer carries the interface, because its warmth
  read as brown in the dark theme.

## Where the values live

The palette feeds the primitive tokens in `tokens.css`. The brand and feedback
base tokens reference a raw named scale drawn from these hues; the neutrals map
the Grey ramp onto `--ds-palette-grey-0` … `--ds-palette-grey-950`, and Black onto
`--ds-palette-black`. Each of those
tokens, with its current value, is listed in the token catalog: the raw scales
under [Palette](/invisible-ui/presentation/token-catalog/#tk-primitive), and the
base tokens that point into them under
[Brand](/invisible-ui/presentation/token-catalog/#tk-brand) and
[Feedback](/invisible-ui/presentation/token-catalog/#tk-feedback). Read the
values there rather than from a copy on this page, so what you read is what
ships.

To retheme, set your own values for the same names; the semantic
`--ds-color-*` roles re-derive automatically:

```css
/* example */
:root {
  --ds-palette-grey-0: #ffffff;
  --ds-palette-grey-900: #101828;
  --ds-palette-dioxazine-purple-500: #1f6feb;
}
```

See [Tokens](/invisible-ui/presentation/tokens/) for the role mapping.
