### Accessibility

- `role="tree"` with roving tabindex; Up/Down move between visible rows,
  Left/Right collapse/expand (or move to parent/child), Home/End jump to ends,
  Enter/Space select.

### Example

```svelte
<TreeView label="Files" nodes={[{ value: "src", children: [{ value: "index.ts" }] }]} expanded={["src"]} />
```

In Elements, assign structured data through properties. Attribute reflection is
reserved for scalar values:

```html
<ds-tree-view id="files" label="Files"></ds-tree-view>
<script type="module">
  import "@design-system/elements/define";

  const tree = document.querySelector("#files");
  tree.nodes = [{ value: "src", children: [{ value: "index.ts" }] }];
  tree.expanded = ["src"];
  tree.addEventListener("selected-change", (event) => {
    tree.selected = event.detail.selected;
  });
</script>
```

### Large trees

Tree View does not virtualize rows. DOM virtualization can remove the focused
treeitem and makes the sibling metadata difficult to keep truthful. For large
remote collections, keep search, filtering, and paging in the application and
assign only the current result forest to `nodes`. Use stable `value` strings;
`selected` and `expanded` remain controlled when the visible forest changes.

Treat each result or page as the complete tree currently presented to the
user. Announce result counts and page changes outside Tree View.

### Asynchronous children

<Preview>
  <TreeViewAsyncDemo client:visible />
</Preview>

Set `hasChildren: true` and omit `children` for a parent whose children are not
available yet. Expanding it calls `onLoadChildren` with its value and a request
id. Elements emits the equivalent `load-children` event. The component does not
fetch or apply the response.

Reflect the request through `loading`. On success, replace the controlled
`nodes` forest and remove the value from `loading`. On failure, remove it from
`loading` and add it to `loadErrors`. Right Arrow or the disclosure control
retries a failed expanded node.

Keep the latest request id per node and ignore older responses. This prevents a
slow response from replacing newer data. Separate nodes can remain in `loading`
at the same time.

```ts
function onLoadChildren({ value, requestId }) {
  latest.set(value, requestId);
  loading = [...loading, value];

  load(value).then((children) => {
    if (latest.get(value) !== requestId) return;
    nodes = replaceChildren(nodes, value, children);
    loading = loading.filter((entry) => entry !== value);
  });
}
```

The four node forms are distinct:

- `{ value: "file" }` is a leaf;
- `{ value: "folder", children: [...] }` is a loaded parent;
- `{ value: "remote", hasChildren: true }` is an unloaded parent;
- `{ value: "empty", children: [] }` is a completed load with no children.

### Virtualization

Tree View does not virtualize rows. DOM virtualization can remove the focused
treeitem and makes sibling metadata difficult to keep truthful. Measure it
against representative large trees only after controlled search, paging and
asynchronous children have been applied. Virtualization requires a separate
accessibility contract and is not enabled automatically.

Themeable via `--ds-tree-*`.
