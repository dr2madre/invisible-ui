A centered message shown when there is no content to show and nothing has
failed: first run, an empty list, no search results, a cleared inbox. It looks
calm and offers the next step: an illustration, a title, an optional
description, and an action area at the bottom.

### Empty state vs error state

Two different concepts (per Nielsen Norman Group):

- **Empty state** (this component): nothing went wrong, there is simply no
  content yet. The user needs to **get started**, so the action is an
  invitation ("Add a project", "Clear filters").
- **[Error state](/invisible-ui/components/feedback/error-state/)**: something
  *failed* (500, timeout, lost connection). The user needs to **recover**
  (retry, reload, go back).

Same layout, different intent: the two components share their anatomy on
purpose, so a screen can switch between them without moving anything.

### When to use

The three empty moments, each with its own copy:

- **First use**: the feature has never been filled. Explain what will live
  here and invite the first step. *"No projects yet. Create your first
  project to get started."* The default slot can hold a learning cue
  (a short tip, starter links) that teaches how this space gets populated.
- **No results**: a search or filter came back empty. Show the term, suggest
  a correction, and offer a way out. *"No results for 'tofu'. Check the
  spelling or try a broader search."* with a "Clear search" action.
- **Cleared by the user**: the work is done (an emptied inbox, a completed
  list). Celebrate quietly with `status="success"`. *"All done. Nothing
  needs your attention."*

One timing rule: the empty state appears only after the data has answered.
While the request runs, show a
[Loading](/invisible-ui/components/feedback/loading/) or a
[Skeleton](/invisible-ui/components/feedback/skeleton/); declaring "nothing
here" during a load misleads. The full cycle (initial moment, query running,
then content, empty or error) is a composition pattern on the backlog.

### Anatomy & reuse

It composes existing primitives, no new behavior:

- **Illustration**: the space at the top accepts your own artwork through the
  `illustration` slot (an SVG, an image, anything). Without it, the theme's
  [FeedbackIcon](/invisible-ui/components/feedback/feedback-icon/) renders as
  the fallback (`neutral` by default, so the tone stays calm).
- **Actions**: [Buttons](/invisible-ui/components/forms/button/) and
  [Links](/invisible-ui/components/navigation/link/). One inviting button
  comes from `actionLabel`/`onAction`; a configurable group comes from the
  `actions` prop: an array of `{ label, onAction, variant, href }` where the
  first action renders in the `default` variant and the rest in `ghost`
  (unless an entry sets its own `variant`), and an entry with `href` renders
  as a link (e.g. "Learn more" documentation). For anything else, the
  `actions` slot replaces the whole area. Omit all three for no actions.
- **Density**: `size="sm"` compacts padding, icon and title for use inside
  cards, panels and table areas; the default `md` fits pages and sections.

### Accessibility

- The region is a `role="status"` (a polite live region): when content
  resolves to empty, the change is announced without interrupting what the
  user is doing.
- Meaning never rests on color alone: the title carries it (WCAG 1.4.1).
- `headingLevel` (default `2`) sets the title's heading level so it fits the
  surrounding document outline.

### Example

```svelte
<EmptyState
  title="No projects yet"
  description="Create your first project to get started."
  actionLabel="Add a project"
  onAction={() => createProject()}
/>
```

Themeable via `--ds-empty-state-*` (gap, padding, max-width, icon size,
illustration max-width, title size).
